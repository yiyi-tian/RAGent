# 客户端命令执行

在任务目录运行 `ragent`；该目录是本连接固定工作区，文件不会随断连删除。
远程模型只提出 `run_command(command, cwd=".")`，客户端 C 策略层重新解析完整 Bash
语法树并决定执行环境。服务端提供的等级、确认值及路径不构成本地授权。

| 等级 | 判定 | 执行环境 | 确认 |
|---|---|---|---|
| 1：观察 | 静态白名单只读参数，不写入、不联网、不读取凭证 | 客户端宿主机，Landlock与seccomp限制，只执行固定程序 | 自动 |
| 2：本地变更 | 已知文件变更、输出重定向等 | rootless容器，真实工作区读写挂载 | 每条命令 |
| 3：向外行动或不确定 | 网络、凭证、解释器、动态扩展、未知程序 | 同上，网络及凭证另行授权 | 每条命令 |

命令链按全部片段的最高等级处理；管道、条件列表、子shell、重定向、替换和解释器均参与分析。
无法静态证明只读的解释器不在宿主机执行。语法错误直接拒绝，不尝试修复后执行。
只读白名单不等于支持所有参数；未覆盖的参数进入容器确认或明确失败。

## 首次部署

完成README中的C构建后，在客户端设备执行：

```bash
bash scripts/setup-command-runtime.sh
export PATH="$HOME/.local/bin:$PATH"
cd /你的任务目录
ragent --host 127.0.0.1 --port 9000
```

该脚本安装独立rootless Docker服务，构建命令及网络代理镜像，安装用户级客户端和资源回收服务。
镜像从固定校验和的Ubuntu 24.04 amd64基础文件系统构建，需要联网下载软件包；首次构建较慢。
日常运行不构建镜像，不改变默认Docker上下文。其他架构尚未验收。
服务端使用 `config/agent.json` 中的 `/tasks`；客户端与服务端均须使用TCP v2。
仅CHAT/RAG的客户端可加 `--remote-only`，该选项禁用本地命令，不会代替用户批准。

## 确认与凭证

写入前显示完整命令、工作区、等级、风险、执行时限和授权清单，最后询问：

```text
即将执行：<完整命令原文>
风险等级：中或高
可能风险：<具体风险>
是否执行？[是/否]
```

只有本地TTY输入“是”才执行；非交互输入不批准。控制字符转义后展示，命令不截断。
拒绝结束整个任务，不改写命令重试。默认执行120秒，可逐条设置1至600秒；只读命令10秒。排队、容器准备和命令执行共用本次执行时限，清理另有短时限。
输出合计最多64 KiB，本机最多4个业务命令同时执行。授权等待不占用服务端工作线程或模型槽。

第三级命令先填写本次网络清单，例如 `https://example.com:443`、`ssh://git.example.com:22`。
必须写协议、完整域名和端口；空行表示无网络。不支持IP、通配符、自动子域授权和执行中扩张清单。
重定向、依赖下载或git子模块涉及其他域名时同样需要事先列出；缺失时失败，不自动重试。

可以分别输入环境凭证和本机凭证文件。环境值隐藏输入；本机文件须为当前用户拥有、
至多1 MiB的普通文件，创建内存运行目录中的只读快照，映射到
`/run/ragent/credentials/<用户填写的文件名>`，不挂载原始宿主机目录。
凭证环境变量不得覆盖PATH、代理、动态加载器或执行器控制项。
SSH约定文件名为 `ssh_key` 和 `known_hosts`；严格检查主机密钥，不自动信任新主机。
加密私钥可单独提供环境凭证 `RAGENT_SSH_PASSPHRASE`，由容器内askpass读取。
宿主机SSH agent、Docker配置和其他凭证不注入容器。
使用凭证的命令输出只在本地展示，服务端和模型只收到状态及输出已隔离的说明。

## 隔离与实际影响

工作区在容器中固定为 `/workspace`，cwd仅允许工作区内相对目录。根文件系统只读，
临时目录使用tmpfs；512 MiB内存、1 CPU、128进程，capabilities全部移除，启用seccomp与
no-new-privileges。容器内UID 0映射为宿主机普通用户，以保证新文件归属正确，不授予宿主机root。
系统控制目录不能作为工作区；执行器安装目录、敏感文件名、硬链接及宿主机Unix Socket等被遮蔽。
只读列目录可能显示受保护文件名，但不能读取其内容。默认敏感名包括 `.env*`、私钥扩展名、`.ssh`、`.aws`、`.config`、`.local` 等。
可以在客户端用户的 `~/.config/ragent/protected-names` 中追加文件名模式，每行一项，
支持fnmatch通配符，`#`开头为注释，不接受目录分隔符。文件须归当前用户所有且不可由其他用户写入；
配置在进程启动后首次使用时读取，修改后重启客户端。只能追加保护，不移除默认规则。
这是路径保护，不承诺识别任意名称文件中的所有秘密；选择工作区前应清理不应暴露的资料。

执行容器始终为 `--network none`。获得网络授权后，单条命令使用独立代理容器，
只通过专用Unix Socket连接，代理不发布宿主机TCP端口；工作容器不获得Docker套接字或外部网卡。
代理只允许获准的协议、域名和端口，拒绝私有地址；HTTPS检查ClientHello的SNI与CONNECT目标一致，
随后透传TLS，不安装代理CA。SSH对获准目标提供CONNECT通道，不提供任意地址转发。
授权远程端点本身可能转发数据，域名限制不等于防泄密；提供凭证的命令能够读取并发送获准凭证。

取消、超时或断连会停止进程并删除容器，已经完成的写入保留，不能视为回滚。
客户端异常退出后，用户级 `ragent-command-reaper.service` 根据PID、启动时刻和boot ID回收遗留资源。
隔离不可用时失败，不降级为宿主机Shell。容器边界不防御具有同一宿主机用户权限的其他恶意进程。
