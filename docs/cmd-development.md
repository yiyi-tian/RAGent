# CMD 命令工具开发方向

目标是让 CMD 能执行真实操作并解释结果，同时让 AGENT 复用这些工具。
按“只读操作 → 沙箱写操作”推进。当前已实现固定诊断和rootless临时工作区；自动写操作仅限连接工作区。

## 职责与目录

| 部分 | 职责 | 建议目录 |
|---|---|---|
| Python 工具 | LangChain 工具声明、参数校验、调用执行器、结果回填 | `python/ragent/tools/` |
| C 执行器 | 权限落实、实际执行、超时与输出限制、子进程回收 | `src/executor/` |
| C 公共接口 | 输入输出、所有权与失败方式声明 | `include/executor/` |
| 测试 | 执行器及 Agent 闭环验证 | `tests/executor/`、`tests/agent/` |

现有 C 网络服务继续负责 TCP 接入与 HTTP 转发，不在 epoll 线程执行命令。
根目录 `tools/` 用于开发、运维和评测脚本。

## 开发顺序

1. 选择有实际用途的只读操作，例如内存、磁盘或进程诊断，先跑通一项完整闭环。
2. 确定 Python 与 C 的调用方式、输入输出格式和权限策略，再扩展工具种类。
3. 建立沙箱与工作区边界，验证隔离可用后逐项开放写操作。

工具名称、命令输入形式、进程间通信方式及具体限额由实现阶段确定；本文不指定
固定程序清单、参数组合或传输方案。自动写操作限于约定沙箱，隔离不可用时不得裸执行。

## 现有协议与接入标准

以下沿用现有约定，详细定义见 [TCP 协议](protocol.md)和[模块接口](module-interfaces.md)：

- 客户端继续使用 CMD_REQUEST 或 AGENT_REQUEST，业务体为包含 query 的 JSON 对象。
  C 服务通过现有 HTTP 接口交给 Python Agent，不为每种命令增加 TCP 消息类型。
- CMD 提供操作工具，AGENT 可组合检索与操作工具；CHAT、RAG 不提供命令执行能力。
- 工具使用结构化参数。模型实际返回的 tool_call_id 与工具结果一一对应，结果作为
  ToolMessage 回填；不能伪造调用历史。
- 最终响应沿用原 request_id。成功响应保留 text、sources、actions；每项操作摘要
  使用 tool、status、summary，status 为 success 或 failed。
- 工具失败应明确回填，部分失败保留已成功步骤。使用既有错误码：COMMAND_NOT_ALLOWED、
  COMMAND_TIMEOUT、COMMAND_OUTPUT_LIMIT、COMMAND_FAILED；过载使用 SERVER_BUSY，
  内部异常使用 INTERNAL_ERROR。若错误作为顶层 ERROR 返回，需同步 C HTTP 适配器的映射。
- 日志保留定位信息，对外输出受限，不包含密钥或私有堆栈。

## 执行器接口需要明确的事项

当前诊断与工作区接口见[模块接口](module-interfaces.md#首批只读执行器接口)。
后续扩展操作或引入写操作前，继续明确以下事项：

| 项目 | 需要明确的内容 |
|---|---|
| 调用方式 | 如何启动或连接执行器，如何处理取消、停止及连接失败 |
| 请求 | 操作或命令如何表达、参数范围、权限上下文及长度限制 |
| 结果 | 成功与失败、输出与退出信息、部分结果及错误码的表达 |
| 资源 | 超时、输出量、并发限制、描述符所有权和子进程回收 |
| 写操作 | 沙箱工作区、路径与权限边界、冲突及失败后的实际状态 |

命令权限必须在 C 执行边界落实，不能只依赖模型或 Python 校验。
写操作超时不能等同于未执行，不应在未明确语义时自动重试。

## 验收方向

只读阶段验证 CMD 与 AGENT 的真实调用，以及拒绝越权、超时、输出超限、部分失败和
子进程回收；写操作阶段增加隔离、路径逃逸和失败状态验证。已有 CHAT、RAG、网络与
并发测试应保持通过。

交付同步工具说明、配置、客户端帮助及实际测试结果，不把待实现能力标为已完成。
